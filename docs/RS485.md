This document provides a comprehensive hardware reference for the industrial RS-485 interface module integrated into the VMC Buddy architecture. Designed for high reliability in electrically noisy environments, this interface bridges standard 3.3V UART logic to differential RS-485 signaling, making it ideal for robust multi-drop communication protocols (such as Modbus RTU or custom industrial command sets).

**Key Features:**

* **3.3V Logic Compatibility:** Direct interfacing with modern microcontrollers (e.g., ESP32, STM32) without level shifters.
* **Industrial-Grade Overvoltage Protection:** Integrated asymmetrical Transient Voltage Suppression (TVS) tailored specifically for RS-485 bus topologies.
* **Automated State Safety:** Hardware-level pull-down mechanisms to prevent bus contention during MCU boot and initialization phases.
* **Selectable Termination:** On-board provision for 120Ω bus termination to accommodate various network topologies (end-node vs. mid-node).

The physical layer strictly adheres to the **TIA/EIA-485-A** standard for balanced multi-point data transmission systems.

* **Signaling Type:** Differential, Half-Duplex.
* **Maximum Cable Length:** Up to 1200 meters (at baud rates ≤ 100 kbps, decreasing logarithmically at higher speeds).
* **Maximum Node Count:** Up to 32 standard unit loads on a single bus segment without repeaters.
* **Differential Output Voltage:** Min. 1.5V (with 54Ω load), Max. 3.3V.
* **Receiver Input Threshold:** ±200 mV.
* **Common-Mode Voltage Range:** -7V to +12V.

| Pin Name | Description | Signal Standard |
| --- | --- | --- |
| **RS485-A** | Non-inverting differential receiver input / driver output. | EIA/TIA-485 |
| **RS485-B** | Inverting differential receiver input / driver output. | EIA/TIA-485 |
| **GND** | Reference Ground (Recommended for long-haul runs to equalize common-mode voltage differences between isolated nodes). | 0V Reference |

| Signal Name | Direction | Function | Nominal Voltage |
| --- | --- | --- | --- |
| **UART-RS485-TX2** | Input (from MCU) | Serial data to be transmitted onto the RS-485 bus. | 3.3V LVCMOS |
| **UART-RS485-RX2** | Output (to MCU) | Serial data received from the RS-485 bus. | 3.3V LVCMOS |
| **RS485-TX-EN** | Input (from MCU) | Direction control toggle. HIGH = Transmit, LOW = Receive. | 3.3V LVCMOS |
| **VCC3V** | Power | Regulated transceiver power supply. | 3.3V DC |
| **GND** | Ground | Common system ground. | 0V |

When writing firmware for the host microcontroller to interface with this RS-485 module, standard UART peripherals can be utilized, provided the software accurately manages the half-duplex direction control pin (`RS485-TX-EN`).

**Transmit/Receive State Machine:**

1. **Idle State:** Ensure `RS485-TX-EN` is held **LOW**. The UART RX interrupt should be enabled to listen for incoming packets.
2. **Pre-Transmission:** Drive `RS485-TX-EN` **HIGH**. Allow a minimal stabilization delay (typically 1-2 microseconds) before initiating the UART transmission.
3. **Data Transmission:** Send the data buffer out via the MCU's hardware UART TX channel.
4. **Post-Transmission / Flush:** *Critical Step.* Do not immediately pull `RS485-TX-EN` low upon pushing the last byte into the UART FIFO. The software must poll the UART's "Transmit Shift Register Empty" flag to ensure the final bit (including the stop bit) has fully exited the MCU before switching back to receive mode.
5. **Return to Listen:** Drive `RS485-TX-EN` **LOW** immediately after the physical transmission completes to free up the bus and listen for responses.
